=====================================================================
TASK 3: READ PREFERENCE (consistency and performance)
=====================================================================

REM Modes:
REM   primary             -> default. All reads from primary. Strongest consistency.
REM   primaryPreferred    -> primary, but secondary if primary is down.
REM   secondary           -> only secondaries. Reads may be slightly stale.
REM   secondaryPreferred  -> secondary, but primary if no secondary is available.
REM   nearest             -> lowest network latency member (any member).

----- 3.1 Set read preference in the shell -----

C:\Users\Student> mongosh "mongodb://localhost:27017,localhost:27018,localhost:27019/?replicaSet=rs0"
rs0 [primary] test> use collegeDB
switched to db collegeDB

rs0 [primary] collegeDB> db.getMongo().getReadPrefMode()
primary

rs0 [primary] collegeDB> db.getMongo().setReadPref("secondary")
rs0 [primary] collegeDB> db.getMongo().getReadPrefMode()
secondary

----- 3.2 Set read preference per query -----

rs0 [primary] collegeDB> db.employees.find({ department: "Engineering" }).readPref("secondary")
rs0 [primary] collegeDB> db.employees.find({ department: "Engineering" }).readPref("nearest")
rs0 [primary] collegeDB> db.employees.find({ department: "Engineering" }).readPref("primaryPreferred")

----- 3.3 Set read preference in the connection string -----

C:\Users\Student> mongosh "mongodb://localhost:27017,localhost:27018,localhost:27019/?replicaSet=rs0&readPreference=secondaryPreferred"

----- 3.4 Prove which member served the read -----

rs0 [primary] collegeDB> db.employees.find().readPref("primary").explain().serverInfo.port

----- 3.5 maxStalenessSeconds (avoid very stale secondaries) -----

C:\Users\Student> mongosh "mongodb://localhost:27017,localhost:27018,localhost:27019/?replicaSet=rs0&readPreference=secondary&maxStalenessSeconds=120"

=====================================================================
TASK 4: WRITE CONCERN (Ensuring data durability)
=====================================================================

REM Write concern = how many members must confirm a write before it is acknowledged.
REM   w: 0          -> no acknowledgement (fire and forget)
REM   w: 1          -> primary only (default for older versions)
REM   w: "majority" -> majority of voting members (default in MongoDB 5.0+)
REM   w: 3          -> a specific number of members
REM   j: true       -> wait until written to the on-disk journal
REM   wtimeout      -> max time (ms) to wait for the acknowledgement

----- 4.1 Check the default write concern -----

rs0 [primary] collegeDB> db.adminCommand({ getDefaultRWConcern: 1 })
{
  defaultWriteConcern: { w: 'majority', wtimeout: 0 },
  defaultReadConcern: { level: 'local' },
  ok: 1
}

----- 4.2 Different write concerns -----

rs0 [primary] collegeDB> db.employees.insertOne({ _id: 7, name: "Arjun", department: "Engineering", salary: 55000 }, { writeConcern: { w: 1 } })
{ acknowledged: true, insertedId: 7 }

rs0 [primary] collegeDB> db.employees.insertOne({ _id: 8, name: "Kavya", department: "Management", salary: 63000 }, { writeConcern: { w: "majority", wtimeout: 5000 } })
{ acknowledged: true, insertedId: 8 }

rs0 [primary] collegeDB> db.employees.insertOne({ _id: 9, name: "Ishaan", department: "Analytics", salary: 59000 }, { writeConcern: { w: 3, j: true, wtimeout: 5000 } })

=====================================================================
TASK 5: ELECTIONS (Handling primary failure)
=====================================================================

REM Election rules:
REM   - Members send heartbeats every 2 seconds.
REM   - If the primary is not heard from for 10 seconds (electionTimeoutMillis),
REM     an eligible secondary calls an election.
REM   - A candidate needs votes from a MAJORITY of voting members (2 of 3).
REM   - The member with higher priority and the most up-to-date oplog is favoured.
REM   - Each election increases the "term" number.
REM   - Without a majority, NO primary is elected and the set becomes read-only.

----- 5.1 Check current state -----
